# Architecture

## System Overview

AppAnalyst is a single-page application with 10 numbered tool sections, supporting tools, and a personal origin story — loaded via classic `<script>` tags. No build step, no bundler, no server required.

```
Browser (file://)
  │
  ├── index.html          HTML shell + section structure (~1,500 lines)
  ├── css/*.css            8 stylesheets (tokens → responsive)
  ├── img/                 Family photos for origin story section
  └── js/
      ├── data/*.js        9 data files (pure arrays/objects)
      ├── app.js           Entry point + observers
      ├── [tool].js        Tool-specific modules
      └── [ui].js          Navigation, modes, keyboard, animations, delight
```

## Load Order

Scripts load synchronously in this order. Dependencies flow downward.

```
1. Data files        (no dependencies)
2. storage.js        (safeStorage wrapper; must load before any persistence caller)
3. app.js            (globals: toast, IntersectionObserver, interaction counter)
4. journey.js        (defines showTip/hideTip used by other modules)
5. fhda.js           (defines markHomeRows, sortFHDAFirst — called by monitor/lookup)
6. Tool modules      (monitor, tracer, flow, patterns, kb, barriers, outreach, lookup, ai-vision, comms)
7. UI modules        (nav, animations, modes)
8. keyboard.js       (references all toggle functions from modes, nav)
9. delight.js        (confetti, micro-interactions — runs last, no dependents)
```

`storage.js` is ordered before `app.js` because tool modules call `safeStorage.get()` at module load time (e.g. `lookup.js` invokes `renderLookup(getFilteredColleges())` on first execution, which reads the college overlay store). If a module can't find `safeStorage`, it silently falls through to a raw `localStorage` try/catch — no crash, but errors become invisible. Keep the ordering intact when adding new modules.

## Persistence & Safety

### Storage wrapper (`js/storage.js`)

All production writes flow through `safeStorage.set(key, value)`, which catches three failure modes that Pass 1 silently dropped:

1. **Safari partitioned storage / private-browsing mode.** `localStorage` access itself throws; `safeStorage` probes once at load and sets `available = false`.
2. **`QuotaExceededError`.** Mobile Safari shares a ~5 MB cap across the origin; a few hundred tickets with long notes can trip it. `safeStorage.set` returns `false` and surfaces a toast that tells the user to back up and archive — they learn immediately instead of losing the next ticket they type.
3. **Corrupt JSON on read.** `safeStorage.get` wraps `JSON.parse` in a try/catch and falls back to the provided default rather than throwing. A corrupt store warns once and gets overwritten on next save.

Call sites include `tickets.js` (`tlLoad`/`tlSave`), `lookup.js` (college overlay), `kb.js` (knowledge base entries), `realTracer.js` (diagnostic state), and `backup.js` (restore from JSON import). Lower-traffic preferences (theme, role, filter state) still use raw `localStorage` because the data is small and a write failure is benign — we don't need to fire a toast for a missed theme toggle.

### XSS threat model

The site is single-user and `localStorage`-only, so XSS is self-inflicted — the threats are:

- **Paste-and-persist.** An analyst paste-bombs a ticket symptom containing `<img src=x onerror=...>`; the string round-trips through storage and gets rendered as HTML on the next page load.
- **Malicious backup import.** A backup file crafted to contain script tags in ticket fields, imported via `backupImportAll`, then rendered by `tlRender`.

Mitigation is escape-on-render. Every user-input field that flows into `innerHTML` is passed through a small `*Esc(s)` function that rewrites `&`, `<`, `>`, and `"` to entities before interpolation:

```js
function tlEsc(s) {
  return (s || '').replace(/&/g, '&amp;').replace(/</g, '&lt;')
                  .replace(/>/g, '&gt;').replace(/"/g, '&quot;');
}
```

The pattern repeats per-module (`tlEsc`, `clEsc`, `rtEsc`) rather than being centralized, so the escape stays colocated with the renderer it protects. The ticket list row renderer (`tickets.js` in `tlRender`) escapes `symptom`, `college`, `system`, and `status` before building the row markup; earlier passes interpolated `t.symptom` raw, which was the main stored-XSS vector.

Inline `onclick` handlers still use `t.id` directly — these IDs are generated by `tlId()` (`'T' + Date.now().toString(36) + rand`) and are never user-writable, so they're not a vector. Be careful about this invariant if you ever add a ticket-ID migration path.

### What's deliberately left alone

- Theme and role preferences write small, bounded strings. A missed write is a silent no-op on next load, which is fine.
- `kbMdToHtml` escapes at the start of rendering, then applies markdown transforms. The order matters: escape first, then transform, so `**bold**` survives but `<script>` doesn't.
- College names in `colleges.js` are a static, shipped-with-the-code data file — not user input — so inline `onclick="clToggle('...')"` patterns that interpolate them are safe as long as no college name contains an apostrophe that the existing `.replace(/'/g, "\\'")` doesn't handle. Audit on every data update.

## Origin Story Section

The origin story (`#originStory`) is a personal "why" section placed between `</main>` (after the last tool section) and `<footer>`. It is **not** numbered and does **not** appear in the TOC or progress dots navigation.

- **Static HTML** — no JS module, no data file
- **Photos** — `img/family-1.jpg` through `img/family-3.jpg` with `onerror` fallback to a CSS placeholder state (`.origin-photo-placeholder`)
- **CSS** — all styles in `css/sections.css` under the `.origin-story` block
- **Layout** — alternating photo/text grid beats, a centered quote card, and a closing statement

## Delight Layer

`js/delight.js` is a game-dev-inspired joy layer loaded last. It adds confetti particle effects and micro-interactions. Respects `prefers-reduced-motion` and reduces particles on mobile. No other modules depend on it.

## Presentation Modes

| Mode | Key | CSS Class | Purpose |
|------|-----|-----------|---------|
| Zoom | `Z` | `.zoom-mode` | Screen-share readability (larger fonts, thicker borders) |
| Theater | `F` | `.theater-on` | Focus mode (dims non-hovered sections) |
| Accessibility | `A` | `.a11y-mode` | WCAG AAA (high contrast, no animations, thick focus rings) |

All modes toggle a class on `<body>`. CSS handles the rest via body-class specificity.

## Extending

### Add a new tool section

1. **Data**: Create `js/data/newtool.js` with a `var` declaration
2. **Module**: Create `js/newtool.js` with render/interaction functions
3. **HTML**: Add a `<section>` in `index.html` following the existing pattern
4. **CSS**: Add section-specific styles to `css/sections.css`
5. **Script tags**: Add both `<script src>` tags to `index.html` (data before module)
6. **Nav**: Add a nav link in the `.nav-links` div and a TOC entry

### Add a new data source

Add a `var` declaration in the appropriate `js/data/*.js` file. All data is global scope — no imports needed. Reference it directly in your module.

### Add a keyboard shortcut

Add a case to the `keydown` handler in `js/keyboard.js`. Follow the existing pattern:
```js
case 'KeyX': scrollToSection('newSection'); toast('New Section'); break;
```

### Utilities available to all modules

- `toast(message)` — Show a brief notification (defined in `app.js`)
- `trackInteraction(name)` — Increment interaction counter (defined in `app.js`)
- `showTip(event, html)` / `hideTip()` — Hover tooltips (defined in `journey.js`)
- `sortFHDAFirst(array)` — Sort Foothill/De Anza to top (defined in `fhda.js`)
- `markHomeRows()` / `markHomeLookups()` — Add FHDA badges (defined in `fhda.js`)

### Modify FHDA awareness

`js/fhda.js` controls all FHDA-specific behavior: home badges, sorting, health display. The helper functions are called by `renderMonitor()` and `renderLookup()` at the end of each render cycle. Colleges with `.fhda = true` in the data arrays are treated as home colleges.

### CSS naming conventions

- `.sec` — Section container
- `.tool-frame` > `.tool-bar` > `.tool-body` — Standard tool wrapper
- `.tool-label.tl-{color}` — Colored label in tool bar
- `.eyebrow` — Section type label above h2
- `.sec-num.sec-num-{color}` — Numbered badge in eyebrow
- `.[section]-*` — Section-specific classes (e.g., `.lookup-*`, `.tracer-*`)
